# Logs and Analytics Guide

This document explains where logs are stored and how to analyze them in the Telegram FAQ Bot project.

## Log Locations

### 1. Main Bot Log
- **Location**: `logs/bot.log`
- **Format**: JSON lines (one JSON object per line)
- **Content**: 
  - Bot startup information
  - User interactions and messages
  - Query matching results
  - File sending operations
  - Error messages
  - Database operations

### 2. Training Log
- **Location**: `training.log` (in the project root directory)
- **Format**: Text log
- **Content**: Model training progress and statistics

### 3. Database
- **Location**: `data/analytics.db`
- **Content**: 
  - User authentication records
  - Query statistics
  - Unanswered questions
  - Bad words logging
  - User activity tracking

## Log Analysis Tools

### 1. Built-in Analytics Tool
The project includes a built-in analytics tool for analyzing bot logs:

```cmd
# Basic usage - shows statistics in console
python tools/aggregate_stats.py

# Export to CSV file
python tools/aggregate_stats.py --csv-export bot_statistics.csv

# Analyze specific log file
python tools/aggregate_stats.py --log-file logs/bot.log

# Show only top 10 queries
python tools/aggregate_stats.py --top-queries 10

# Export to CSV only (no console output)
python tools/aggregate_stats.py --csv-export bot_statistics.csv --csv-only
```

### 2. Database Analysis
You can also analyze data directly from the SQLite database:

```cmd
# Export database statistics to text file
# This is automatically done when you run certain bot commands
```

The database contains tables for:
- `authenticated_users`: User authentication records
- `unanswered_questions`: Questions that couldn't be answered
- `query_stats`: Query matching statistics
- `bad_words_log`: Records of inappropriate messages

## Generated Reports

### 1. CSV Statistics Report
- **Location**: `bot_statistics.csv` (generated by analytics tool)
- **Content**: Export of all log entries in CSV format for spreadsheet analysis

### 2. Text Analytics Reports
- **Location**: `analytics_report_YYYYMMDD_HHMMSS.txt` (generated by bot)
- **Content**: 
  - Total query statistics
  - Success rates
  - Popular queries
  - Unanswered questions
  - Bad words statistics
  - Authenticated users count

## Log Rotation

The bot implements log rotation:
- Logs are automatically rotated when they reach 10MB
- Up to 5 backup files are retained
- Old log files are compressed to save space

## Troubleshooting

### Common Issues:

1. **Encoding Problems**: 
   - The log files may use different encodings (UTF-8, CP1251)
   - The analytics tool automatically tries multiple encodings

2. **Permission Issues**:
   - Ensure you have read permissions for log files
   - Run the analytics tool from the project directory

3. **File Not Found**:
   - Check that the bot has been run at least once
   - Verify the log directory exists

### Viewing Logs Manually:

```cmd
# View last 20 lines of log
type logs\bot.log | more

# Search for specific entries
findstr "User message" logs\bot.log

# Count total lines
find /c /v "" logs\bot.log
```

## Best Practices

1. **Regular Analysis**: 
   - Run analytics regularly to understand usage patterns
   - Monitor unanswered questions to improve FAQ content

2. **Log Maintenance**:
   - Use the built-in log rotation
   - Archive old logs for historical analysis
   - Clean up unnecessary log files with `3_Clean_All.bat`

3. **Privacy Considerations**:
   - Log files may contain user IDs and chat information
   - Handle log data according to privacy policies
   - Be careful when sharing log files
