# Анализ проекта FAQ Bot

## Общее описание

Проект FAQ Bot представляет собой интеллектуальную систему вопросов и ответов на базе Telegram бота с семантическим поиском. Система состоит из двух основных компонентов:

1. **faq_bot** - Python-приложение для Telegram с использованием aiogram
2. **faq_loader** - C# приложение для обработки данных FAQ

## Архитектура системы

### Компоненты

#### FAQ Bot (Python)
- **Телеграм-интерфейс**: Обработка сообщений пользователей через Telegram API
- **Семантический поиск**: Использование Sentence-BERT для поиска релевантных ответов
- **Аутентификация**: Система контроля доступа с парольной защитой
- **Хранение данных**: SQLite для аналитики и аутентификации
- **Кэширование**: Механизмы кэширования для повышения производительности

#### FAQ Loader (C#)
- **Обработка данных**: Анализ и структурирование FAQ данных
- **Семантическая группировка**: Алгоритмы для группировки похожих вопросов
- **Смарт-линковка**: Создание связей между вопросами
- **Интерфейс**: WPF приложение для управления процессом

### Поток данных

1. FAQ Loader обрабатывает исходные данные и создает:
   - `faq.json` - структурированный набор FAQ
   - `analytics.db` - база данных для аналитики и аутентификации

2. FAQ Bot использует эти файлы для:
   - Поиска ответов на вопросы пользователей
   - Аутентификации пользователей
   - Сбора аналитики

## Технический стек

### Основные технологии
- **Python 3.8+** - основной язык для бота
- **aiogram** - фреймворк для Telegram бота
- **Sentence-Transformers** - для семантического поиска
- **FAISS** - для эффективного поиска в векторном пространстве
- **SQLite** - для хранения данных
- **C# (.NET 6.0)** - для приложения обработки данных

### Зависимости
- numpy, pandas - для работы с данными
- openpyxl - для работы с Excel файлами
- python-dotenv - для управления конфигурацией
- psutil - для мониторинга производительности

## Оптимизация для VPS

### Проблемы производительности
VPS с характеристиками Intel Xeon 2 ГГц (1 ядро), 512 МБ ОЗУ, 10 ГБ HDD представляет следующие ограничения:

1. **Ограниченная память**: 512 МБ RAM может быть недостаточно для загрузки больших моделей
2. **Ограниченная производительность CPU**: 1 ядро ограничивает параллельную обработку
3. **Ограниченное дисковое пространство**: 10 ГБ требует эффективного использования места

### Решения
1. **Оптимизация параметров модели**:
   - Уменьшение размера батча с 16 до 8
   - Снижение размера кэша с 500/1000 до 100/200

2. **Эффективное управление ресурсами**:
   - Сохранение обученных моделей для избежания повторного обучения
   - Очистка временных файлов без удаления моделей

3. **Мониторинг состояния**:
   - Скрипты проверки состояния системы и бота
   - Логирование для диагностики проблем

## Порог схожести

Порог схожести установлен на 0.7 (был 0.73), что позволяет:
- Увеличить количество найденных совпадений
- Снизить строгость поиска для лучшего пользовательского опыта
- Компенсировать возможные неточности в семантическом поиске
